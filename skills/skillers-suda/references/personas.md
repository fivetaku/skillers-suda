# Personas Catalog — 도메인별 4 페르소나 정의

> 인원수 4는 검증 다중성의 본질로 유지. 페르소나 정의는 도메인에 맞게 가변.
> 4명이 서로 다른 관점에서 아이디어를 검증하면 SKILL.md 품질이 안정화된다.

---

## 사용 방법

Phase B 진입 전, 사용자 아이디어의 도메인을 추정하여 4명을 선택한다:

1. 도메인이 일반/모호한 경우 → **기본 set** 사용
2. 도메인이 명확한 경우 (헬스케어, 이커머스, 보안 등) → **도메인 특화 set** 사용
3. 도메인이 카탈로그에 없으면 → 사용자에게 4명을 자유 정의하도록 인터뷰 (**인원수 4는 유지**)

페르소나 4명 모두 `general-purpose / sonnet / bypassPermissions`로 병렬 스폰 (현행 유지).

## 기본 set (default — 도메인 미특정 시)

| 페르소나 | 핵심 질문 | 검증 영역 |
|---|---|---|
| 기획자 | "누가 쓸 건데? 뭘 해결하는 거야?" | 방향성, 사용자 정의, 가치 명확성 |
| 사용자 | "나라면 이걸 어떻게 쓸까?" | UX, 진입장벽, 일상 사용 |

| 검수자 | "이거 이 경우에도 돼?" | 엣지 케이스, 안티패턴 |

## 도메인이 카탈로그에 없는 경우

사용자에게 인터뷰로 4명을 정의받는다:

```
이 아이디어의 도메인이 [카탈로그에 없는 도메인]이네요.
4명의 전문가를 정의해주세요 (인원수 4는 검증 다중성의 본질이라 유지):

1. [방향성을 잡는 사람] = ?
2. [실제 사용자 입장] = ?
3. [기술/도메인 전문가] = ?
4. [엣지 케이스 잡는 사람] = ?
```

또는 **기본 set**을 사용하고, 도메인 특화는 각 페르소나의 프롬프트에서 자유 narrative로 보강.

---

## ⚠️ 절대 규칙

1. **인원수 4는 유지** — 검증 다중성이 SKILL.md 품질의 본질
2. **페르소나 4 모두 다른 관점이어야 함** — 같은 관점 4명은 다양성 손상
3. **personas.md에 사이트명·브랜드명·특정 회사명 하드코딩 금지** — 도메인별 일반화만 (No-Site-Name Rule 차용)
4. **도메인이 모호하면 기본 set 사용** — 잘못된 도메인 추정으로 부적합한 4명 부르지 말 것
